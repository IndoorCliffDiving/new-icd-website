# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static single-page marketing site for Indoor Cliff Diving (a diving/climbing club in Amsterdam). There's no framework or SSG — the site is two hand-written, near-duplicate HTML documents (Dutch and English) with a small Node build step that injects a live event table before deploy.

## Commands

- Install deps: `npm install`
- Build: `npm run build` (runs `node script.js`)
- No lint is configured, and `npm test` is a placeholder (`echo "Error: no test specified"`) — there is no real test suite.

## Architecture

**Source vs. generated files** — `template.html` (Dutch, the canonical/default page) and `template-en.html` (English) are the files to edit. `output/index.html` and `output/en.html` are generated build artifacts produced by `script.js`; don't hand-edit them except as a stopgap when the build can't be run, and regenerate via `npm run build` afterward to keep them canonical.

**Build step (`script.js`)** — fetches a public Google Sheets CSV (the event calendar, URL hardcoded in the script) and builds an HTML `<table class="agenda">` from it. This table replaces the `<!-- ICD_EVENT_TABLE_CONTENT -->` placeholder inside the `#agenda` section of each template, and the resulting document is minified with `html-minifier` and written to `output/index.html` / `output/en.html`.

**Static assets in `output/`** — `output/css`, `output/js`, `output/img`, `output/fonts`, `output/docs`, `output/corona`, `output/html`, and `output/CNAME` are checked-in static files, not generated by the build. Templates reference them by absolute path (e.g. `/css/style.css`, `/img/logo.png`). When adding/changing assets, edit them directly in `output/` — there's no separate source directory for them.

**Two-language structure, one page each** — Both templates are built from the same anchor-linked sections (`#home`, `#about`, `#portfolio`, `#service`, `#agenda`, `#pricing`, `#team`, `#contact`, `#partners`) driven by the top nav. When editing content in one template, make the equivalent edit in the other to keep them in sync. There's no shared templating/partial system — duplication between the NL and EN files is expected and intentional.

**Language routing** — there's no server-side routing; `index.html` (NL) is served at `/` by default. An inline script near the end of `template.html` redirects to `en.html` if the browser's language starts with `en` and the current page isn't already English. There is no reverse redirect from `en.html` back to NL.

**Deployment (`.github/workflows/deploy.yml`)** — triggered on push to `main`, on a schedule (every 2 hours), or manually. CI runs `npm ci && npm run build`, commits any resulting `output/**` changes back to `main`, then deploys the `output/` folder to the `gh-pages` branch (custom domain via `output/CNAME` → indoorcliffdiving.com). This means `output/` on `main` is a live, source-controlled build cache that can be automatically regenerated/overwritten at any time — don't assume a manual edit there will persist past the next scheduled run.

**External integrations** — Google Tag Manager (`GTM-TBM6RL8`); Trainin.app (`indoorcliffdiving.trainin.app`) for class sign-ups and schedules, linked directly from the templates; a public Google Sheet as the event/agenda data source consumed by `script.js`.
